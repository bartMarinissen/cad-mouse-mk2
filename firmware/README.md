You can customize several variables to tune gains, smoothing, and deadzones for all six axes.
Most of these settings are defined in [`Config.h`](include/Config.h) and are the main place to adjust the overall feel of the device.

There are X, Y, Z for the Translation gains T
And Rx, Ry, Rz for the rotation gains R.

The X axis is side to side (axis between the buttons).  
The Y axis is front to back (axis through the USB-C port).  
The Z axis is vertical, through the main knob

// Gains and sign fixes

## Motion pipeline

Motion comes from a solved 6-DOF pose (Gauss-Newton), not per-axis averaging. `MotionController::compute()` (`src/controllers/MotionController.cpp`) solves the pose from the raw sensor readings, then applies the sign/gain/dead-zone/smoothing table above on top of that solved pose, same as before. See [`../ARCHITECTURE.md`](../ARCHITECTURE.md) for the full pipeline and [`src/magnet_model/README.md`](src/magnet_model/README.md) for the solver internals if you want to experiment with the motion model itself.

`firmware/src/magnet_model/magnet_model_table.h`/`.cpp` (part of that pipeline) is auto-generated by `magnet_field_model/field_approximation.ipynb` — don't hand-edit it, see `src/magnet_model/README.md` for detail.

**Sensor layout** (`include/magnet_model/positions.h`):
- `mag1` = bottom
- `mag2` = top left
- `mag3` = top right
